# Project profile

## About

- What this repository is: `sqlalchemy-foundation-kit`, a Python library with the foundation layer for async SQLAlchemy services on PostgreSQL (session management, Unit of Work, base ORM models, pool metrics and tracing), published on PyPI.
- Who uses it: async services on PostgreSQL that would otherwise write their own engine, session and transaction plumbing, including services behind PgBouncer.
- Language, version and main frameworks: Python 3.11 and newer, async only; runtime dependencies SQLAlchemy 2 (`sqlalchemy[asyncio]`), Pydantic 2 and asyncpg; optional extras `settings` (pydantic-settings), `metrics` (prometheus-client), `orjson`, `dishka`, `dependency-injector`, `telemetry` (OpenTelemetry) and `all`. The integrations are in `sqlalchemy_foundation_kit/contrib/`.
- Where the documentation lives: https://bedrock-python.github.io/sqlalchemy-foundation-kit/, built with Zensical from `docs/` (`zensical.toml`) and deployed by `docs.yml` on every push to `master`. `docs/agents.md` is the one-page reference for coding assistants.

## Commands

| Task | Command |
|---|---|
| Install dependencies | `uv sync --group dev --all-extras` (`make install`), then `uv run pre-commit install --hook-type pre-commit --hook-type commit-msg`. CONTRIBUTING.md runs `uv sync --group dev` without the extras, which the unit tests of `base/serialization` and `contrib/` need (`make test-unit` adds them itself), and it installs only the commit-message hook. |
| Format | `make fmt`: `uv run ruff format .`, then `uv run ruff check --fix .` |
| Lint and type-check | `make check`: `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy sqlalchemy_foundation_kit` |
| Test | `make test-unit` (`uv run --all-extras pytest -m unit`, no Docker). `make test-integration` (`uv run --all-extras pytest -m integration`) needs Docker. `make test` runs the whole suite with `--cov-fail-under=90`. CI runs `uv run pytest -m unit` on every Python version of its matrix, and `uv run pytest -m integration --cov=sqlalchemy_foundation_kit --cov-fail-under=90` once. |
| Run locally | A library: nothing to run. The docs: `make docs-serve`. |
| Stop the local run | Ctrl+C in the terminal of `make docs-serve`. |

## Conventions

- Default branch: `master`. A ruleset on it requires a pull request and the `All checks passed` check (the `all-checks-passed` job of `ci.yml`), and refuses force pushes. The pre-commit hook `no-commit-to-branch` refuses local commits to it.
- Issue tracker: GitHub Issues of this repository; refer to an issue as `#123`.
- Branch names: `<type>/<short-description>`, such as `feat/my-feature` (CONTRIBUTING.md).
- Commit messages: Conventional Commits, enforced by the `conventional-pre-commit` hook. Pull requests are squash-merged (the ruleset would also accept a merge commit, but `master` has none). release-please reads the squash title, so a pull request's title is a Conventional Commit too.
- Language of pull request titles and descriptions: English.
- Where specs and design notes go: in the pull request description; the repository has no place for them.

## Boundaries

- `CHANGELOG.md` is generated by release-please: never edit it by hand, and never add an `## [Unreleased]` section, even though the pull request template's checklist asks for one.
- The version lives in `sqlalchemy_foundation_kit/__version__.py`, on the line marked `# x-release-please-version`, and in `.release-please-manifest.json`; release-please bumps both. Never change them by hand.
- `docs/agents.md` is part of the public API: it changes in the same pull request as the API (CONTRIBUTING.md, "The agents page").
- Files from the engineering-assets hub (`AGENTS.md` explains how it works) include the copy-page files (`docs/assets/javascripts/copy-page.js`, `docs/assets/stylesheets/copy-page.css`, `overrides/main.html`, `scripts/emit_markdown.py`), `.github/workflows/docs.yml`, `.github/workflows/release-please.yml`, `.github/dependabot.yml`, `.editorconfig` and `CODE_OF_CONDUCT.md`. Change them in the hub; a change here makes the file this repository's own.
- Never publish to PyPI or create a release by hand: release-please creates the release, and `publish.yml` publishes it.

## Notes

- Releases: release-please opens its pull request with the workflow's own token, so CI does not start on it, and `master` does not accept it without `All checks passed`. Close and reopen the release pull request to run CI, then merge it. `publish.yml` publishes to PyPI when the Release Please run on `master` completes and a `sqlalchemy-foundation-kit-v*` tag points at its commit. Before 1.0, a breaking change bumps the minor version (`bump-minor-pre-major`).
- Tests: `tests/conftest.py` marks every test `unit` or `integration` by its directory, and the markers are strict (`--strict-markers`). Integration tests start `postgres:17-alpine` through testcontainers. When Docker is not running they are skipped, not failed.
- Coverage: only `make test` enforces 90%. `tests/conftest.py` drops the threshold to 0 when only integration tests run, so CI's `--cov-fail-under=90` is never enforced, and the unit job measures no coverage.
- Python versions: ruff and mypy target 3.11, the lowest supported version, but CI tests only 3.12 and 3.13 (its matrix lists 3.12 twice).
- `contrib/di` is the Dishka integration (extra `dishka`); `contrib/dependency_injector` is the dependency-injector one.
- Code style (CONTRIBUTING.md): type hints on every function, tests included; Google-style docstrings on the public API only; lines up to 120 characters; double quotes; comments only for a non-obvious why.
